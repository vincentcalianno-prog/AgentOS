Layer A / B / C architecture

Layer A — AgentOS. The umbrella repository (the one you cloned, the one Claude Code is operating on). It holds Layer B, Layer C, and eventually other sub-projects beyond ACP (the Daily SCM Agent, MEPA Agent, PO Acceptance Agent live or will live here).

Layer B — WorkflowOS. The platform substrate. Splits into two functional regions: Platform DNA (workflow-agnostic agents that any workflow uses) and Workflow Cells (the agents specific to one workflow — today, contract_redline). When workflow #2 lands, it adds a new set of cells without touching the DNA. This is the DNA/cells framing you've already committed to.

Layer C — Deployment. Antora-specific content that plugs into Layer B at runtime. Three buckets: the playbook (Antora's positions per contract type and category — this is what we're about to draft), skills (LLM-consumable reasoning patterns in SKILL.md format), and deployment config (credentials, routing, SLA thresholds, schema extensions). When a second org deploys ACP, they replace Layer C — Layer A and Layer B stay the same.

The placement of agents inside Layer B is deliberate: Agents 3, 8, 9 sit in Platform DNA because they handle state, orchestration, and cross-workflow aggregation — none of that is workflow-specific. Agents 1, 2, 4–7 sit in Workflow Cells because every step they take (classify a redline email, diff a contract, draft a counter-proposal) is contract_redline-specific.

Contract type & category taxonomies

Two taxonomies, joined by applicability. The contract type taxonomy and the category taxonomy both live as Layer A substrate — they're portable across deployments. Each deploying org reuses the same taxonomies but fills in their own Layer C entries.

Many-to-many relationship. Each contract type has an applicable subset of categories (NDAs don't have warranty; MPAs do). Each category may appear in multiple contract types (confidentiality appears in NDA, MPA, MEPA, MSA, SOW). Antora's playbook fills in a Layer C entry for each applicable pair — not every category × every type.

Per-pair Layer C entries. The bottom box shows the structure: each entry has a preferred position, a fallback, and a reject threshold. The same category (e.g. confidentiality) can have different positions in different contract types — confidentiality in an NDA is the entire point of the document; confidentiality in an MPA is one clause among many. The (contract_type, category) pair is the unit, not just the category.

Today we build the architecture to accommodate NDA / MPA / MEPA / MSA / SOW / PO and fill Layer C content for MPA/MEPA only. NDA and SOW content gets filled when those workflows become real. No speculative substrate extraction — same principle as the rest of ACP.
