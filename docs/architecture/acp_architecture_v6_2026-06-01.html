Authoring Standard · Locked

PlaybookEntry antora_response — three-part block

Every PlaybookEntry must include response language for all three states. No silent accepts, no bare rejects. Counter-language is mandatory. The three fields coexist with accept_modifications and reject_thresholds — those classify supplier redlines; antora_response holds what Antora says back.

REJECT
rejection_response { rationale: str counter_proposal: str }
Risk rationale + clean counter-proposal restoring Antora’s position. Firm language; no hedging on signature blockers.
COMPROMISE
compromise_response { conditions: str revised_language: str }
Why the deviation is tolerable + what revised language Antora will accept. Conditions must be specific.
ACCEPT
acceptance_response { rationale: str }
Why the baseline clause already protects Antora adequately. Not optional — silent accepts are rejected by schema validation.

Loosening is intentionally not handled by overlays. If a supplier counter is less restrictive than the resolved position but Antora’s team wants to accept it, that’s a RuntimeConcession — a separate runtime mechanism with multi-party human authorization, scoped to a single negotiation, never auto-promoted into permanent overlays. Promotion to overlay is a deliberate, reviewed, human act captured as ConcessionPromotion. Deferred overlay axis candidates: geography/jurisdiction, regulatory regime (BAA/IRA/FEOC/ITAR), contract value tier — add on evidence only.

Learning loop — two flows, IP-safe by design

There are two distinct learning flows. Both are accommodated in the schema now; only one crosses the deployment boundary. Execution is deferred to Phase 3+, but outcome_log and abstraction_status are in place from the first Sprint 1 entries.

Flow 1 — Within deployment
Antora learns about Antora. outcome_log → drift detection → Playbook Maintenance Agent surfaces proposed updates → Sandelin approves. Stays entirely inside Layer C. No IP crosses any boundary.
Flow 2 — Across deployments (below)
The platform learns from every deployment. Layer C → Layer B (IP-stripped) → Layer A. This is where Layer A and B learn from Layer C findings. IP-sensitive — the stripping + validation pass is the guardrail.
Layer C — Raw outcome_log
Full IP: counterparty names, pricing, verbatim clause language, Sandelin overrides. Lives in PlaybookEntry.outcome_log. Never leaves Layer C. abstraction_status tracks processing state.
IP validation pass — strips proper nouns, specific figures, verbatim clause language
Layer B: IP Validation Pass
Checks abstraction_status = pending · verifies no IP leakage before registry write
Sets abstraction_status → extracted | skipped | flagged_for_review
↓
Layer B — Pattern Extractor → Shared Learning Registry
Abstracted behavioral patterns only. No proper nouns, no specific figures, no verbatim language.
Example: “signature_blocker positions consistently compromised after 2 rounds → consider tiered opening.”
Registry is a compounding platform asset — benefits all deployments. Org A’s patterns help Org B.
↓
Layer A — Behavioral Refinements
Registry patterns consumed as agent reasoning improvements. Platform becomes smarter with every negotiation across all deployments.
Control principle (non-negotiable): No agent at any layer autonomously updates Antora’s negotiating positions. Playbook Maintenance Agent surfaces proposed updates only. Sandelin approves every position change — not the system.
Must be explicit in the Sandelin IP conversation.
Stability guardrail: Learning lives in the registry and the behavioral refinements agents consult — not in the schema. The 16-entity model and the deployment contract stay fixed. “Layer A learns” means its agents reason with better patterns, not that Layer A rewrites itself. Schema mutation from Layer C findings would be content leaking into substrate — portability breaks.

Playbook Evidence Model

Two-tier evidence model

evidence_tier is epistemic — it indicates counterparty confirmation, not quality. Tier 2 (provisional) entries are real, calibrated positions. Every closed agreement upgrades entries from Tier 2 → Tier 1. The first executed MEPA will be a major calibration event.
